# Day52 小程序会员卡商品入口与购买页面重构计划

更新时间：2026-07-15  
前置依赖：Day49 会员卡商品订单、用户权益卡和分钟核销模型，Day50 商品/权益命名，Day51 首页会员卡和 0 元权益预约闭环均已上线。  
目标：把会员卡商品购买入口统一收口到首页，将“我的会员卡”恢复为纯用户资产页，并建立“首页商品卡片 -> 会员卡商品详情 -> 购买确认 -> 支付 -> 用户订单/我的会员卡”的清晰购买链路。

> “删除‘我的’当中的会员卡购买入口”不等于删除“我的会员卡”。“我的”仍需展示用户已经获得的用户权益卡及其状态、余额、冻结分钟和预约入口；只删除当前卡包页面中的“购买会员卡”商品区和购买按钮。会员卡商品只能从首页进入购买流程。

## 1. 业务名称与页面职责

| 名称 | 业务含义 | Day52 页面职责 |
| --- | --- | --- |
| 会员卡商品 | 用户尚未购买的可售模板版本 | 只在首页商品区、商品详情和购买确认页展示 |
| 会员卡商品订单 | 用户购买会员卡商品形成的交易 | 支付前后均进入“订单 / 会员卡订单” |
| 用户权益卡 | 支付成功后发放给用户的会员资产 | 只在“我的 / 我的会员卡”展示和使用 |
| 会员卡权益预约 | 使用用户权益卡冻结分钟产生的服务预约 | 继续沿用 Day51 的 0 元预约流程 |

ID 语义保持不变：

```text
cardId / cardTemplateId       = 会员卡商品模板 ID
purchaseOrderId               = 会员卡商品购买订单 ID
memberCardId                  = 用户权益卡 ID（UserMemberCard.id）
memberCardConsumeMinutes      = 本次会员卡权益预约核销分钟
```

商品详情和购买确认页只能携带 `cardId`；支付成功发卡后才能取得 `memberCardId`。禁止在购买阶段把模板 ID 当成用户权益卡 ID。

## 2. 当前问题

### 2.1 商品与用户资产混在同一页

当前 `/pages/card/index` 同时加载：

```text
GET /member-cards/my       // 用户已经拥有的权益卡
GET /member-cards/shop     // 尚未购买的会员卡商品
```

页面上半部分是用户权益卡，下半部分是“购买会员卡”。用户从“我的卡包”进入后既能使用已有权益，又能直接购买新商品，导致“我的”同时承担资产管理和商城入口两种职责。

### 2.2 首页会员卡与热门服务结构不一致

热门服务使用两列商品格：封面、名称、短描述、价格、单位和进入箭头。当前会员卡使用横向列表，信息密度和点击预期都与热门服务不同，用户不容易把它理解为同级商品。

### 2.3 点击首页商品后直接进入混合卡包

Day51 首页通过：

```text
/pages/card/index?shopCardId=<模板ID>
```

定位到卡包购买区。该页面既不是会员卡商品详情，也不是纯购买确认页，激活期限、有效期、适用服务、核销分钟和退款边界没有形成完整的阅读顺序。

### 2.4 购买动作缺少确认层

当前卡包“购买”按钮直接创建会员卡商品订单并进入支付结果页。用户没有独立的购买确认页面核对商品版本、总分钟、适用服务、激活期限、有效期和应付金额。

## 3. 目标信息架构

```text
首页
├─ 热门服务
│  └─ 服务商品详情 -> 服务预约/购买
└─ 会员卡
   └─ 会员卡商品详情 -> 购买确认 -> 支付

订单
├─ 服务预约
└─ 会员卡订单

我的
└─ 我的会员卡
   ├─ 未激活
   ├─ 使用中
   └─ 已完成
```

唯一购买入口链路：

```text
首页会员卡商品
-> /pages/member-card/detail?id=<cardId>
-> /pages/member-card/purchase?id=<cardId>
-> 创建 member_card_purchase 订单
-> /pages/payment/result
```

购买成功后的数据落点：

```text
会员卡商品订单 -> 订单 / 会员卡订单
发放的用户权益卡 -> 我的 / 我的会员卡
立即预约产生的任务 -> 订单 / 服务预约
```

## 4. “我的”页面调整

### 4.1 保留资产入口

`miniapp/src/pages/profile/index.vue` 保留会员卡统计入口，但统一改名：

```text
我的卡包 -> 我的会员卡
```

统计值继续读取 `getMyMemberCards()` 的用户权益卡数量，点击进入 `/pages/card/index`。该入口的含义固定为“查看我已经获得的会员卡”，不再表达购买。

### 4.2 “我的会员卡”只显示用户资产

`miniapp/src/pages/card/index.vue` 调整为：

1. 只调用 `getMyMemberCards()`。
2. 删除 `getPurchasableMemberCards()`、`createMemberCardPurchaseOrder()` 和 `buyCard()`。
3. 删除 `shopCardId`、首页购买来源参数、商品定位和“购买会员卡”整个区块。
4. 页面标题从“我的卡包”改为“我的会员卡”。
5. 保留用户权益卡状态、剩余分钟、冻结分钟、激活/到期时间和“去预约”。
6. 空态改为“暂无会员卡 / 购买完成后将在这里展示”，不提供直接购买按钮或跳到商品详情的快捷入口。
7. 购卡成功页携带 `userMemberCardId` 进入时，仍应定位并突出新发放的用户权益卡。

“我的会员卡”不能因为删除商品区而删除 Day51 的统一会员卡权益预约能力。

## 5. 首页会员卡商品区

### 5.1 与热门服务统一商品结构

会员卡商品采用与热门服务相同的两列商品格和稳定尺寸：

```text
商品封面
会员卡名称
差异化短描述
价格 / 张
进入箭头
```

首页会员卡商品和热门服务共享同一展示组件或同一组布局约束：

```text
cover / title / description / price / unit / fallbackIcon
```

共享组件只负责展示，不在组件内判断服务或会员卡业务类型；点击行为由首页分别处理。

### 5.2 差异化短描述

短描述不能统一写成“购买后自动入卡包”，而应根据当前会员卡商品字段生成：

| 数据条件 | 首页描述示例 |
| --- | --- |
| 有适用服务名称 | `720分钟 · 适用日常保洁` |
| 多个适用服务 | `720分钟 · 日常保洁等3项服务` |
| 有激活期限 | `购买后30天内激活 · 有效90天`，详情页完整展示 |
| 自定义核销分钟 | `每次可选60/120分钟` |
| 固定核销 | `每次核销120分钟` |

首页商品格只显示一行主要短描述，激活期限和有效期进入详情页展开，避免两列卡片高度不一致。

### 5.3 商品封面

Day52 默认不新增会员卡数据库封面字段。展示优先级为：

1. 结构化适用服务中的首个有效服务封面。
2. 会员卡类型对应的现有静态商品视觉资产。
3. 会员卡图标占位。

为避免前端额外请求每个服务详情，`GET /member-cards/shop` 和详情接口可在现有 `serviceRuleList` 读模型中补充首个适用服务的 `coverImage/coverImageDisplayUrl`；这是返回模型扩展，不需要 Prisma migration。

如果后续要求 Admin 为每张会员卡独立上传营销封面和自定义文案，应另开商品内容字段迁移，不在 Day52 前端改造中临时硬编码。

### 5.4 点击与数量

点击商品统一进入：

```text
/pages/member-card/detail
?id=<会员卡商品模板ID>
&source=home_member_card
```

删除首页跳转 `/pages/card/index?shopCardId=...` 的旧行为。

首页默认最多展示 6 个可售会员卡商品，与热门服务首屏数量一致。超过 6 个时使用首页区块内“展开更多/收起”，不把“我的会员卡”重新当成商品列表入口。

## 6. 会员卡商品详情页

新增：

```text
miniapp/src/pages/member-card/detail.vue
```

路由：

```text
/pages/member-card/detail?id=<cardId>&source=home_member_card
```

### 6.1 与服务详情保持一致的页面骨架

页面结构与 `/pages/service/detail` 保持一致：

```text
顶部商品封面
商品名称 + 简介 + 价格
权益内容
适用服务与核销规则
激活和有效期规则
购买与使用流程
购买须知
底部价格 + 下一步
```

一致的是视觉层级、封面比例、内容区间距和底部操作栏；描述内容必须按会员卡业务重新组织，不能复制“师傅上门、完成服务”等单次服务详情文案。

### 6.2 差异化详情内容

#### 权益内容

```text
总权益：720 分钟
核销口径：按分钟
卡状态：支付成功后未激活
```

#### 适用服务与核销规则

按 `serviceRuleList` 每项展示：

```text
服务名称
固定核销 / 半次核销 / 自定义核销
默认核销分钟
最小核销分钟
可选分钟档位
```

禁止只展示旧 `applicableServices` 中的原始字符串。结构化规则不存在时，详情页显示兼容说明并只展示服务端能够确认的有效服务；不能把“2”“小时”等旧拆分值显示给用户。

#### 激活与有效期

```text
支付成功 -> 发放未激活用户权益卡
购买后 N 天内完成首次预约激活
首次成功冻结权益后开始计算有效期
激活后 N 天有效
到期后完成原因为 expired
```

#### 购买须知

至少明确：

1. 会员卡商品购买本身不产生师傅任务。
2. 只有使用权益预约服务后才生成服务预约。
3. 预约时按照所选服务规则冻结分钟，师傅完成后核销实际分钟并释放未使用冻结。
4. 未激活、未冻结且未核销的卡可按现有流程申请退款；其他情况进入售后审核。

### 6.3 底部操作

详情页底部显示商品价格，主按钮文案为“下一步”。点击后进入购买确认页，不直接创建订单。

未登录用户点击“下一步”时进入登录页，并完整保留详情页到购买确认页的 redirect。商品已下架时禁用按钮并显示“当前不可购买”。

## 7. 会员卡购买确认页

新增：

```text
miniapp/src/pages/member-card/purchase.vue
```

路由：

```text
/pages/member-card/purchase
?id=<cardId>
&source=home_member_card
```

### 7.1 页面内容

购买确认页只处理会员卡商品交易，不混入用户权益卡预约：

```text
商品名称与版本
总权益分钟
适用服务摘要
激活期限
激活后有效期
核销规则摘要
商品原价
优惠金额（后续接入优惠券时）
应付金额
购买须知确认
确认购买按钮
```

页面加载时重新调用 `getPurchasableMemberCardDetail(cardId)`，不得信任首页或详情页通过 query 传递的价格、分钟或规则。

### 7.2 创建订单

用户点击“确认购买”后：

```text
POST /member-cards/purchase-orders
{
  cardId,
  source: 'home_member_card'
}
```

创建成功后进入：

```text
/pages/payment/result
?orderId=<purchaseOrderId>
&orderType=member_card_purchase
&status=pending
&amount=<server payableAmount>
```

必须防止按钮重复点击和重复创建订单。服务端继续作为商品状态、模板版本和应付金额的最终权威。

### 7.3 暂不购买

购买确认页允许返回会员卡商品详情，不提供跳转“我的会员卡”的按钮。用户资产页不是商品购买流程的一部分。

## 8. 支付完成后的双落点

Day52 不改变 Day49/Day51 的支付和发卡事务：

```text
支付确认
-> 会员卡商品订单 status=completed
-> MemberCardPurchaseOrder 保存售出版本快照
-> 发放 UserMemberCard.pending_activation
```

### 8.1 订单

`/pages/order/list` 保留两种视图，文案统一为：

```text
服务预约
会员卡订单
```

购买订单支付前后都能从“订单 / 会员卡订单”找到。会员卡商品订单卡片展示商品名称、交易状态、实付金额和下单时间，不展示服务地址、师傅和预约时间。

### 8.2 我的会员卡

只有服务端确认支付并成功发卡后，用户权益卡才出现在“我的 / 我的会员卡”。支付结果页继续等待：

```text
order.status=completed
memberCardPurchase.grantedUserMemberCardId > 0
```

“查看我的会员卡”进入 `/pages/card/index?userMemberCardId=<ID>` 并定位新卡。

### 8.3 立即预约

购卡成功后的“立即预约”继续复用 Day51 `navigateToMemberCardReservation()`：单一服务直接进入 0 元预约页，多服务先选择服务。该入口使用发放后的用户权益卡 ID，与本次购买页面的模板 ID 严格分离。

## 9. 路由与旧链接兼容

新增路由：

```text
pages/member-card/detail
pages/member-card/purchase
```

旧路由处理：

| 旧入口 | Day52 行为 |
| --- | --- |
| `/pages/card/index?shopCardId=<id>` | 兼容重定向到 `/pages/member-card/detail?id=<id>`，观察一个版本后删除 |
| `/pages/card/index?userMemberCardId=<id>` | 保留，用于定位已发放的用户权益卡 |
| “我的卡包” | 改名“我的会员卡”，仍进入 `/pages/card/index` |
| 首页“查看全部”进入卡包 | 删除；商品在首页内展开，或后续新增独立商城页 |

登录 redirect 必须保留 `id/source`，返回栈不能把用户送回“我的会员卡”购买区，因为该购买区已删除。

## 10. 数据与接口范围

### 10.1 继续复用

```text
GET  /member-cards/shop
GET  /member-cards/shop/:id
POST /member-cards/purchase-orders
GET  /member-cards/my
GET  /orders?orderType=member_card_purchase
GET  /orders/:id
POST /orders/:id/pay
```

### 10.2 返回模型补充

为首页封面和差异化详情，`PurchasableMemberCard.serviceRuleList` 建议补充只读字段：

```text
serviceDescription
serviceCoverImage
serviceCoverImageDisplayUrl
```

这些字段来自现有 `services` 表和图片签名能力，不新增会员卡表字段，不执行数据库迁移。

如果结构化 `serviceRuleList` 为空，服务端需要输出清洗后的兼容服务摘要；前端不得继续直接解析历史 `applicableServices` 的混合字符串作为完整商品详情。

## 12. 实施步骤

1. 固定四类页面职责与路由契约，补充 `PurchasableMemberCard` 商品展示 DTO。
2. 服务端扩展可售会员卡列表/详情读模型，返回适用服务名称、描述、封面和结构化核销规则；添加返回模型测试。
3. 提取首页商品展示组件或统一布局，将会员卡商品改为与热门服务一致的两列结构。
4. 新建会员卡商品详情页，按卡的分钟、期限和服务规则生成差异化内容。
5. 新建购买确认页，完成二次详情加载、须知确认、防重复提交和购买订单创建。
6. 精简“我的会员卡”，删除所有商品接口、购买按钮和购买区，只保留用户权益卡及预约入口。
7. 调整订单页、订单详情和支付结果页文案，核对购买订单和发放用户权益卡的双落点。
8. 增加旧 `shopCardId` 深链兼容，检查登录 redirect 与页面返回栈。
9. 执行 Miniapp 类型检查、微信小程序构建、Server 构建和购买/发卡回归，再完成微信 Android/iOS 真机支付验收。

## 14. 验收标准

1. “我的 / 我的会员卡”页面不存在任何可售会员卡商品、商品价格或购买按钮，只展示用户已经获得的权益卡。
2. “我的”统计入口文案为“我的会员卡”，数字等于当前用户权益卡总数。
3. 首页是会员卡商品购买的唯一业务入口，旧入口只做临时重定向，不形成第二个商城。
4. 首页会员卡商品与热门服务使用一致的两列商品结构、封面比例、标题/描述/价格层级和稳定高度。
5. 每张会员卡首页描述由自身权益和服务规则生成，不使用统一静态描述。
6. 点击首页商品进入独立会员卡商品详情页，页面骨架与服务详情一致，但内容完整解释会员卡权益、服务规则、激活和有效期。
7. 商品详情“下一步”进入独立购买确认页，未确认前不创建订单。
8. 购买确认页重新从服务端获取商品详情和应付金额，防重复提交且不信任路由价格。
9. 创建后的会员卡商品订单立即出现在“订单 / 会员卡订单”；未支付时不发放用户权益卡。
10. 支付并发卡完成后，用户权益卡出现在“我的 / 我的会员卡”，并可定位、查看状态和使用权益预约。
11. 购卡成功立即预约继续显示应付 0 元，且不影响师傅任务、地址、冻结和核销闭环。
12. Day49-Day51 的订单、发卡、退款、到期、冻结、核销和释放回归测试全部通过。
13. Miniapp 类型检查和微信小程序构建通过，详情/确认页在 Android/iOS 真机无文本溢出、重复下单或错误返回栈。

## 15. 明确不做

1. 不删除“我的会员卡”资产入口，只删除该页面中的会员卡商品购买功能。
2. 不把会员卡商品订单和用户权益卡合并成一条前端数据。
3. 不在首页商品卡片点击时直接创建订单或直接调起支付。
4. 不在商品详情页选择服务地址和预约时间；购卡不是服务预约。
5. 不在购买确认页生成师傅任务；只有使用权益创建服务预约后才进入师傅端。
6. 不修改用户权益卡三态、完成原因、激活期限、有效期和分钟核销账本。
7. 不为 Day52 临时硬编码某张卡的名称、服务或营销文案。
8. 不执行数据库迁移；独立会员卡封面和运营文案字段如确有需要，另行规划 Admin 与数据库内容模型。
